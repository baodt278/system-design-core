UUID v7:            100,000 lượt chèn = 2.8 giây  (gần bằng INT!)

Giải Pháp 2: Twitter Snowflake
@56
Khái Niệm
@57
**Snowflake = ID 64 bit, sắp theo thời gian, duy nhất trên toàn cục**
@58
Cấu trúc 64 bit:
┌─────────────────────────────────────────────────┐
│ 1 │      41 bit      │  10 bit │     12 bit    │
│   │  dấu thời gian   │    ID   │   số thứ tự   │
│ 0 │   (mili giây)    │   máy   │     bộ đếm    │
└─────────────────────────────────────────────────┘

@59
**Phân tích chi tiết:**
@60
Bit 0 (1 bit):
- Luôn là 0 (dự trữ, bit dấu)

Bit 1-41 (41 bit): Dấu thời gian
- Số mili giây kể từ mốc epoch (epoch tuỳ chỉnh)
- 2^41 ms ≈ 69 năm
- Sắp xếp được theo thời gian!

Bit 42-51 (10 bit): Machine ID
- Xác định máy nào đã sinh ra ID
- Hỗ trợ 2^10 = 1,024 máy
- Được cấu hình khi khởi động

Bit 52-63 (12 bit): Số thứ tự
- Bộ đếm trong cùng một mili giây
- 2^12 = 4,096 ID mỗi mili giây trên mỗi máy
- Đặt lại mỗi khi sang mili giây mới

@61
**Tính toán năng lực:**
@62
Mỗi máy:
- 4,096 ID/mili giây
- 4,096,000 ID/giây
- ~350 tỷ ID/ngày

1,024 máy:
- 4.2 triệu ID/giây trên toàn hệ thống
- 360 nghìn tỷ ID/ngày

Quá đủ!

Vấn Đề ⟦Lệch Đồng Hồ|Clock Skew⟧
@68
**Vấn đề:**
@69
Đồng hồ máy A: 10:00:00.000
Đồng hồ máy B: 10:00:05.000 (nhanh hơn 5 giây)

Máy B sinh ra: ID = 1000005000...
Máy A sinh ra: ID = 1000000000... (nhỏ hơn!)

ID từ máy A < ID từ máy B về giá trị
nhưng lại được sinh ra SAU về thời gian!

→ Thứ tự bị phá vỡ

**Giải pháp:**
@71
1. Đồng bộ NTP (khuyến nghị)

   - Giám sát độ lệch đồng hồ
   - Cảnh báo nếu độ lệch > ngưỡng

2. Từ chối sinh ID nếu đồng hồ chạy lùi
   - Kiểm tra: current_time < last_time
   - Báo lỗi hoặc chờ
   - Đánh đổi: Tính sẵn sàng giảm

3. Dùng đồng hồ logic (Lamport, Vector)
   - Không phụ thuộc vào đồng hồ thực
   - Cài đặt phức tạp

Phát Biểu Vấn Đề
@87
Dịch vụ A (Máy 1):
- Sự kiện 1 xảy ra lúc 10:00:00.000 → Sinh ID = 100
- Sự kiện 2 xảy ra lúc 10:00:00.001 → Sinh ID = 101

Dịch vụ B (Máy 2, đồng hồ nhanh hơn 5ms):
- Sự kiện 3 xảy ra lúc 10:00:00.003 → Sinh ID = 108

Dòng thời gian:
Sự kiện 1 (10:00:00.000) → ID = 100
Sự kiện 2 (10:00:00.001) → ID = 101
Sự kiện 3 (10:00:00.003) → ID = 108

Sắp xếp theo ID:
100 < 101 < 108 ✓ Đúng thứ tự

Nhưng nếu đồng hồ Máy 2 bị lệch:
Sự kiện 1 (10:00:00.000) → ID = 100
Sự kiện 3 (10:00:00.003) → ID = 95  (đồng hồ Máy 2 chạy chậm!)
Sự kiện 2 (10:00:00.001) → ID = 101

Sắp xếp theo ID:
95 < 100 < 101 ✗ Sai thứ tự! (Sự kiện 3 phải ở cuối)

   → Machine ID ngăn xung đột

3. Thứ tự hoàn hảo, bắt buộc phải phối hợp
   → Máy chủ sinh ID tập trung
   → Điểm lỗi duy nhất
   → Điểm nghẽn
   → Không mở rộng được
